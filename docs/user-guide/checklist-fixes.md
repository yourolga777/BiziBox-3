# Чек-лист проверки фиксов v2.1.0

Проверяются только исправления из набора «чиним сейчас»:
**1) сосуществование с занятым портом 7910 · 2) спам-тоггл сохраняет сферу · 3) экспорт CSV · 4) иконка трея.**

Пройти по порядку. Результат: **пройдено** / **ошибка** (с описанием).

## 0. Подготовка

- [ ] Взять свежую сборку: `backend\dist\BiziBox.exe` (portable) или `installer\dist\installer\BiziBox-Setup-2.1.0.exe`.
- [ ] Скопировать `BiziBox.exe` в **чистую** отдельную папку, например `D:\BiziBox\`.
- [ ] Убедиться, что порт 7910 занят «чужим» инстансом (это обязательное условие для проверки №1):
      открыть `http://127.0.0.1:7910/api/health` — порт должен отвечать (любой инстанс, не наш свежий).

## 1. Сосуществование с занятым портом 7910

- [ ] Запустить новый `BiziBox.exe` двойным кликом. Окно консоли не появляется; в трее иконка.
- [ ] Браузер открылся в режиме инкогнито на **свободном** порту (`7911`…`7925`), а **не** на 7910.
- [ ] Health нового экземпляра отвечает:
      `http://127.0.0.1:<ваш порт>/api/health` → `{"app":"BiziBox","version":"2.1.0","status":"ok"}`.
- [ ] Чужой процесс не пострадал: `http://127.0.0.1:7910/api/health` по-прежнему отвечает (тот же инстанс).
- [ ] Приложение не закрывается само сразу после старта (раньше был мгновенный shutdown из-за SO_REUSEADDR).
- [ ] UI показывает **свои** данные (онбординг/свои контакты), а не окно чужого инстанса.

## 2. Спам-тоггл сохраняет прежнюю сферу

> Автопроверка: backend `tests/test_contacts_crm.py` (set_spam → restore previous_life_sphere, 434 passed),
> frontend vitest 183 passed (MessageDetail/MessageToolbar/SpamFeedDialog/ContactDetailPanel — спам через `contactApi.setSpam`).
> Результат: **пройдено (автотесты)**.

- [x] Создать контакт со сферой **«Личное»** → пометить его спамом → сфера стала «Спам».
- [x] **Снять** спам → контакт вернулся в **«Личное»** (не «пусто», не дефолт).
- [x] Создать контакт **без сферы** → пометить спамом и снять → остался **без сферы**, не потерялся из списков, виден при фильтре «не спам».

Требует ручного смоука в UI (см. раздел 6).

## Если что-то упало

1. Зафиксируйте: номер пункта, что делали, что увидели (текст ошибки / скриншот / адрес порта).
2. Проверьте health: `http://127.0.0.1:<порт>/api/health` — отвечает или нет; укажите порт.
3. Посмотрите `data\logs\bizibox.log` и приложите фрагмент ERROR к обращению.

# Чек-лист проверки BiziBox v2.1.0 с инструкциями

Пройдите пункты по порядку. Отмечайте результат: **пройдено** / **ошибка** (с описанием).
Для каждого раздела — короткая инструкция «как проверить».

---

## 0. Подготовка

- [ ] Взять свежую сборку: `backend\dist\BiziBox.exe` (portable) и/или `installer\dist\installer\BiziBox-Setup-2.1.0.exe`.
- [ ] Для portable: скопировать `BiziBox.exe` в **чистую отдельную папку**, например `D:\BiziBox\`.
- [ ] Перед стартом проверить, что на порту 7910 ничего не висит:
      в браузере открыть `http://127.0.0.1:7910/api/health`. Если отвечает — этот инстанс считается «чужим» (например, старый BiziBox/IziBox).

## 1. Установка и запуск

- [ ] Portable: запустить `BiziBox.exe` двойным кликом.
      Инструкция: окно консоли/терминала появляться **не должно** — приложение работает в фоне, в трее появляется иконка (синий квадрат с буквой **B**).
- [ ] Браузер открылся в режиме **инкогнито** на `http://127.0.0.1:7910` **или** на следующем свободном порту (`7911`…`7925`), если 7910 занят.
      Проверить фактический порт: в трее у иконки BiziBox «Открыть BiziBox» должен вести на работающий адрес.
- [ ] Health-проверка: `http://127.0.0.1:<порт>/api/health` отвечает `{"status":"ok","version":"2.1.0","app":"BiziBox"}`.
- [ ] **Сосуществование с занятым 7910:** пока другой инстанс держит 7910, запустить второй `BiziBox.exe`.
      Ожидаемо: второй встаёт на свободный порт (например 7911), показывает **свой** UI, **не** выскакивает на чужой инстанс и **не** убивает чужой процесс (чужой `http://127.0.0.1:7910/api/health` продолжает отвечать).
- [ ] Третий запуск (при уже запущенном BiziBox) не заводит третий процесс дубликатом: повторно открывает окно уже работающего инстанса, данные не теряются.

## 2. Онбординг

- [ ] Первый запуск показывает экран приветствия (онбординг), а не пустую страницу и не 500.
      Инструкция: заполнить логин и пароль → сохранить. После — попадаете внутрь (Дашборд или Входящие).
- [ ] Рядом с exe появилась папка `data\users\<ваш_логин>\` с файлом базы данных.
- [ ] Неверные/пустые данные онбординга показывают понятную ошибку (не «500»).
- [ ] Файл `.env` рядом с exe создан автоматически и содержит сгенерированные `SECRET_KEY` / `ENCRYPTION_KEY` (production-стиль, не `dev-encryption-key...`).

## 3. Каналы (Telegram / Email)

- [ ] Страница «Каналы»: можно добавить подключение (Telegram / Email).
- [ ] Канал отображается со статусом «подключён» / «отключён», ошибки подключения понятные.
- [ ] При добавлении Telegram через код подтверждения: код вводится, при неверном — понятная ошибка.

## 4. Входящие и сообщения

- [ ] Во «Входящих» появляются сообщения из подключённых каналов.
- [ ] Ответ уходит в «Отправленные» (Outbox).
- [ ] Прочитано/непрочитано, архив, удаление работают.
- [ ] Поиск по тексту находит нужное сообщение.

## 5. Контакты — классификация (сфера, типы, папки)

- [ ] Создать контакт: имя + **сфера** (Личное / Рабочее / Спам) — сохраняется.
- [ ] У контакта можно проставить **типы** (Клиент, Поставщик, Друг и т.п.) — больше одного; типы можно создавать/переименовывать/удалять на странице контактов.
- [ ] Контакту выбирается **папка**; папки создаются с подпапками.
- [ ] **Ошибка 400 (не 500):** попробовать сохранить контакт с папкой из другой сферы (папка «Рабочее», а сфера «Личное») → понятное сообщение об ошибке.
- [ ] **Ошибка 422 (не 500):** сфера не из списка (Личное/Рабочее/Спам) отклоняется с понятным сообщением.

## 6. Контакты — спам-тоггл (важно: возврат сферы)

- [ ] Пометка «спамом»: контакт со сферой «Личное» помечается спамом → переходит в сферу Спам.
- [ ] **Снятие спама:** убрать пометку → контакт возвращается в **прежнюю сферу** («Личное»), а не «в пустоту» и не «в дефолт».
- [ ] Контакт **без сферы**: пометить спамом и снять → остаётся **без сферы** (не теряет данные, в списках виден, не пропадает при фильтре «не спам»).
- [ ] Спам-контакт не приходит во «Входящие» как обычное сообщение.

## 7. Контакты — прочее

- [ ] Заметки сохраняются и редактируются.
- [ ] День рождения → событие в календаре.
- [ ] Важность (избранное) работает.
- [ ] Поиск контактов по имени/телеграму/почте работает.

## 8. Дашборд

- [ ] Дашборд открывается со статистикой (непрочитанные, всего сообщений, контакты, задачи).
- [ ] Фильтры по сфере/типу не теряют контакты без сферы.

## 9. Задачи, календарь, напоминания

- [ ] Задача создаётся (заголовок, дата, статус, приоритет).
- [ ] Повторяемая задача видна в нужные дни.
- [ ] Календарь показывает события и задачи с датами.
- [ ] Невалидный статус задачи → понятное 422, не «500».

## 10. Настройки

- [ ] Страница «Настройки» открывается; тема (светлая/тёмная) переключается и сохраняется.
- [ ] Интервал опроса Telegram/Email меняется и сохраняется.

## 11. Экспорт / импорт / бэкап

- [ ] **Экспорт контактов в CSV** — кнопка «Экспорт» на странице контактов скачивает `.csv` без ошибки «Ошибка при экспорте».
- [ ] Импорт контактов из CSV (включая **тестовые CSV** с заведомо битыми строками): валидные строки импортируются, битый CSV отклоняется с понятной ошибкой, не «500».
- [ ] Бэкап скачивается (зашифрованный файл).
- [ ] Восстановление из бэкапа возвращает данные.

## 12. Завершение и лог

- [ ] «Выход» через трей полностью останавливает приложение: порт освобождается (`http://127.0.0.1:<порт>/api/health` перестаёт отвечать).
- [ ] Повторный запуск: данные на месте (БД, контакты, каналы).
- [ ] В `data\logs\bizibox.log` нет строк уровня ERROR.

---

## Если что-то упало

1. Зафиксируйте: пункт чек-листа, что делали, что увидели (текст ошибки / скриншот).
2. Посмотрите `data\logs\bizibox.log` рядом с exe — там видно причину.
3. Проверьте health: `http://127.0.0.1:<порт>/api/health` — отвечает или нет.
4. Приложите фрагмент лога к обращению.

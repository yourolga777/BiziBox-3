# Этап 5 — Миграции БД → Alembic 🔴

> Вставь сюда блок из `00-context.md` перед прогоном.

## Цель

Перевести ad-hoc миграции в управляемые Alembic-ревизии, чтобы будущие обновления (в т.ч. ввод owner_id) были безопасными и предсказуемыми.

## Текущее состояние (зафиксировано)

- Alembic установлен, `backend/migrations/` содержит 5 ревизий, но **в рантайме не используется** — ни одного упоминания `alembic` в коде `app/` и `scripts/`.
- Реальная схема мигрируется в `init_db()` через `app/services/migration_service.py` (764 строки):
  - ~25 ad-hoc функций `ALTER TABLE ... try/except pass`
  - отдельный механизм одноразовых миграций через `PRAGMA user_version` (8 штук)
  - сидирование: `seed_contact_type_templates`, `seed_default_folders`, `seed_default_categories`
  - фиксы данных: `fix_mime_subjects`, дедупликация
- `backend/app/ai/migrations/` — пустая заглушка (только `__init__.py`).

## Файлы для изучения

- `backend/app/services/migration_service.py`
- `backend/migrations/` — Alembic-ревизии
- `backend/app/database.py` — `init_db()`
- `backend/scripts/` — одноразовые скрипты

# Этап 2 — Авторизация и безопасность 🔴

> Вставь сюда блок из `00-context.md` перед прогоном.

## Важная установка по объёму

Полный auth (JWT/login, регистрация, восстановление пароля) **отложен в релиз 2** и в рамках этого этапа НЕ проектируется как реализация. В релизе 1 вводится только интерфейс `get_current_user` (см. Решение 3 в `01-data-model-multi-user.md`).

**Задача этого этапа:**
1. Оценить корректность и безопасность интерфейса `get_current_user` и плампинга `owner_id` под будущий JWT.
2. Найти уязвимости ТЕКУЩЕГО кода (которые важно закрыть до релиза 1, даже при одном пользователе).
3. Дать рекомендации по безопасности, которые можно заложить сейчас и развернуть в релизе 2.

## Вопросы

1. Оцени интерфейс `get_current_user`: как он должен выглядеть, чтобы в релизе 2 достаточно было подменить только реализацию (JWT-разбор) без правок сервисов/репозиториев?
2. Какие текущие эндпоинты не защищены даже от базового доступа (нет проверки авторизации вообще)?
3. OWASP: какие векторы уязвимы в текущем коде уже сейчас (SQL-инъекции, XSS, IDOR, SSRF, path traversal)?
4. Как обеспечить изоляцию данных между пользователями (owner-scope в сервисах и репозиториях) — согласуется ли с Решением 2 из Этапа 1?
5. Как защитить admin-функции (миграции, import/export, настройки каналов) в будущем?
6. Какие секреты из `.env` могут попасть в код, логи или ответы API?
7. Корректны ли текущие rate-лимиты slowapi (60/minute глобально)?
8. Где Pydantic-валидация не покрывает входные данные?
9. Допустимы ли текущие `ALLOWED_ORIGINS` в CORS-конфигурации?
10. Что шифруется через Fernet и где хранятся ключи шифрования? Не попадают ли в код?
11. Нет ли утечки чувствительных данных в логгер (`logger` в коде)?
12. Как должен выглядеть полный auth-дизайн для релиза 2 (JWT access+refresh, сроки, logout/revocation), чтобы его можно было реализовать позже без ломки текущего кода?

## Ожидаемый результат

- Оценка интерфейса auth-зависимости для будущего JWT.
- Список уязвимостей текущего кода с приоритетами (что закрыть до релиза 1).
- Дизайн-макет auth для релиза 2 (без реализации).
